# T3 Code execution

Use the app-owned orchestration tools exposed in this session. Discover their live
schemas/capabilities rather than assuming standalone Codex agent files configure
T3 children. Pass the role contract explicitly in each task assignment.

For a child needing an isolated checkout use `delegate_task` with `isolation:
"worktree"`. It starts from the parent's local commit; uncommitted planning inputs
must be supplied explicitly. Retain taskId and use task_status/task_cancel. Validate
returned provider/model/options and workspace/branch/start SHA against the assignment.
If the tool cannot bind the required baseline/workspace, stop that dispatch and
resolve routing; do not approximate by shell cd or a path in the prompt.

Discover provider/model IDs with orchestrator_capabilities. Preserve requested or
inherited model options through target.options; report unsupported choices. Use
native children only when their workspace and model-option support is sufficient.
For a fresh delegated review round call delegate_task again with a distinct stable
clientRequestId and full brief, prior findings, responses and unresolved objections.
Do not continue a delegated review by messaging its backing childThreadId.

A coordinator needing to leave the primary checkout must use the available T3
workspace handoff and confirm its binding. Do not create a new top-level thread
unless the owner asked for one. Shell worktree creation or cd does not change T3's
binding. Keep integrations serialized in the bound feature workspace.

Reconcile returned task IDs and terminal task state before integrating or removing
workspaces. Do not assume a visible commit or lost response means completion.
Register every created/worked PR with link_pull_request when available, and verify
registration before handoff. Monitoring uses watch_pull_request when available;
children return pending state to their parent rather than starting watchers.
